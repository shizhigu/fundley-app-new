# Analysis Block 架构对比报告

## 背景

当前系统需要确定 Analysis Block（分析块）的组织方式。Analysis Block 是用户进行投研分析的工作单元，包含 Jupyter Notebook、生成的报告（HTML）、数据文件（JSON）等。

---

## 方案对比

### 方案 1：Block 跟随 Chat（层级结构）

**数据结构**：
```
User
└─ Chats (多个对话)
    ├─ Chat A: "分析科技股"
    │   ├─ Block 1: NVDA 分析
    │   ├─ Block 2: AMD 对比
    │   └─ Block 3: 行业趋势
    │
    └─ Chat B: "消费股研究"
        ├─ Block 4: AAPL 分析
        └─ Block 5: TSLA 分析
```

**UI 结构**：
```
┌────────────────────┬────────────────────────────────┬──────────────────┐
│  Sidebar (Chats)   │      Main (Chat)               │  Right (Blocks)  │
├────────────────────┼────────────────────────────────┼──────────────────┤
│ 📁 科技股分析       │  [User]: 分析 NVDA             │  当前对话的块：  │
│ 📁 消费股研究       │  [AI]: 好的，正在分析...        │  ✅ NVDA 分析     │
│ 📁 本周简报         │  [Block: NVDA 分析]            │  ✅ AMD 对比      │
│ + 新对话           │  [User]: 再看看 AMD            │  ✅ 行业趋势      │
│                    │  [AI]: ...                     │  + 新建分析块    │
└────────────────────┴────────────────────────────────┴──────────────────┘
```

**工作流程**：
1. 用户创建新对话："分析科技股"
2. 在对话中，AI 生成多个分析块（NVDA、AMD、行业趋势）
3. 右侧面板显示**当前对话的所有块**
4. 切换到另一个对话，右侧显示**该对话的块**

**优势**：
- **上下文清晰**：块和对话的关系明确，容易追溯"这个分析是在哪次对话中产生的"
- **自动分组**：对话天然形成主题分组，无需手动管理
- **对话完整性**：查看对话历史时，可以完整回顾分析过程
- **符合直觉**：对话 → 结果，逻辑链路清晰

**劣势**：
- **跨对话复用困难**：想在新对话中引用旧分析块较复杂
- **分析块分散**：同一股票的分析可能散落在不同对话中
- **搜索局限**：只能在当前对话的块中搜索，全局搜索需要额外入口
- **切换成本**：想看不同对话的分析块，需要频繁切换对话

### 方案 2：Block 独立于 Chat（扁平结构）

**数据结构**：
```
User
├─ Chats (多个对话，用于交互)
│   ├─ Chat A: "分析 NVDA"
│   ├─ Chat B: "分析 AMD"
│   └─ Chat C: "对比两者"
│
└─ Blocks (独立存储，不归属于 Chat)
    ├─ Block 1: NVDA Q4 财报分析
    ├─ Block 2: AMD Q4 财报分析
    ├─ Block 3: NVDA vs AMD 对比
    ├─ Block 4: 科技股行业趋势
    └─ Block 5: TSLA 估值模型
```

**UI 结构**：
```
┌────────────────────┬────────────────────────────────┬──────────────────┐
│  Sidebar (Chats)   │      Main (Chat)               │  Right (Blocks)  │
├────────────────────┼────────────────────────────────┼──────────────────┤
│ 📝 分析 NVDA        │  [User]: 分析 NVDA Q4 财报      │  🔍 搜索分析块... │
│ 📝 分析 AMD         │  [AI]: 正在创建分析块...        │                  │
│ 📝 对比两者         │  [Block: NVDA Q4 财报分析]      │  所有分析块：    │
│ + 新对话           │  [User]: 再看看 AMD            │  ▼ NVDA Q4 分析   │
│                    │  [AI]: ...                     │  □ AMD Q4 分析    │
│                    │                                │  □ NVDA vs AMD   │
│                    │                                │  □ 科技股趋势    │
│                    │                                │  □ TSLA 估值     │
│                    │                                │  + 新建空白块    │
└────────────────────┴────────────────────────────────┴──────────────────┘
```

**工作流程**：
1. 用户在任意对话中，AI 生成分析块
2. 所有块都显示在右侧面板（全局列表）
3. 用户通过搜索/筛选找到目标块
4. **展开的块 = 当前工作块**，其 block_id 自动传递给 Agent
5. 用户可以手动创建空白块，然后在对话中让 AI 填充内容

**优势**：
- **全局视图**：所有分析块一目了然，容易找到历史分析
- **灵活复用**：可以在任意对话中引用/修改任何块
- **主题聚合**：可以按股票、行业等维度查看所有相关块
- **模板工作流**：创建空白块 → 选择模板 → AI 填充，更像专业工具

**劣势**：
- **溯源困难**：不容易知道"这个分析块是在哪次对话中生成的"
- **需要搜索**：块数量多时，必须依赖搜索/筛选功能
- **认知负担**：用户需要理解"对话是过程，块是结果"的概念
- **状态管理复杂**：需要明确告诉系统"当前在编辑哪个块"

## 典型使用场景对比

### 场景 1：单次深度分析

**需求**：用户想深度分析 NVDA Q4 财报，包括收入、利润率、AI 业务等多个维度。

| 维度 | 方案 1（跟随 Chat） | 方案 2（独立 Block） |
|------|---------------------|---------------------|
| 操作 | 创建对话 "NVDA Q4 分析" → AI 生成多个块 | 创建空白块 "NVDA Q4 分析" → 在对话中让 AI 填充 |
| 结果 | 所有分析块归属于该对话 | 生成一个独立块，包含所有分析 |
| 查看 | 打开该对话，右侧显示所有块 | 在右侧块列表中搜索 "NVDA"，展开查看 |
| 优势 | 对话和结果天然关联 | 块作为独立成果，可在其他对话中复用 |

---

### 场景 2：跨主题复用分析

**需求**：用户之前分析过 NVDA，现在想对比 NVDA 和 AMD。

| 维度 | 方案 1（跟随 Chat） | 方案 2（独立 Block） |
|------|---------------------|---------------------|
| 操作 | 创建新对话 "NVDA vs AMD" → AI 需要重新分析 NVDA（或手动复制） | 创建新对话 → AI 可以直接引用已有的 "NVDA 分析" 块 |
| 结果 | NVDA 块在旧对话中，新对话有独立的 NVDA 块（重复） | 一个 NVDA 块被多个对话引用 |
| 优势 | 每个对话独立完整 | 避免重复分析，节省时间 |
| 劣势 | 可能产生重复内容 | 需要明确引用关系 |

---

### 场景 3：长期投研项目

**需求**：用户跟踪科技股，每周生成新的分析，需要对比历史数据。

| 维度 | 方案 1（跟随 Chat） | 方案 2（独立 Block） |
|------|---------------------|---------------------|
| 组织方式 | 每周创建新对话 "Week 1 科技股"，对话包含多个块 | 所有块平铺，通过日期/标签筛选 |
| 查看历史 | 按对话查看：Week 1, Week 2, Week 3... | 按时间/股票筛选：NVDA (3周数据), AMD (2周数据) |
| 对比分析 | 需要打开多个对话，分别查看块 | 在一个视图中筛选多个时间点的块 |
| 优势 | 时间线清晰（每周一个对话） | 灵活查询（按股票、按时间、按主题） |

---

### 场景 4：模板化分析

**需求**：用户创建了一个标准的"财报分析模板"，希望快速应用到不同股票。

| 维度 | 方案 1（跟随 Chat） | 方案 2（独立 Block） |
|------|---------------------|---------------------|
| 操作 | 在对话中说 "用之前 NVDA 的方法分析 AMD" | 创建空白块 → 复制 NVDA 块的 notebook → 修改参数 |
| 模板管理 | 模板是"某次对话的块"，需要记住在哪个对话 | 可以标记某些块为"模板"，全局可见 |
| 复用流程 | AI 需要理解用户想复用哪次分析 | 用户直接操作块（复制、修改参数） |
| 优势 | 自然语言交互 | 精确控制，类似专业工具 |

## 技术实现对比

| 维度 | 方案 1（跟随 Chat） | 方案 2（独立 Block） |
|------|---------------------|---------------------|
| 数据库关系 | `blocks.chat_id` (外键) | `blocks.user_id` (外键)，chat_id 可选 |
| 文件路径 | `/tmp/fundley/{user_id}/chats/{chat_id}/blocks/{block_id}/` | `/tmp/fundley/{user_id}/blocks/{block_id}/` |
| 右侧面板 | 查询当前 chat 的 blocks | 查询用户所有 blocks |
| 搜索范围 | 当前对话的块 | 用户所有块 |
| 当前块识别 | 自动（当前对话最新块） | 手动（用户展开的块） |
| 跨对话引用 | 需要额外设计（块共享机制） | 天然支持（块本身独立） |

## 混合方案（可选）

**概念**：Block 独立存储，但记录其"来源对话"

**数据结构**：
```typescript
interface AnalysisBlock {
  id: string
  user_id: string
  source_chat_id?: string  // 可选：记录创建时的对话
  title: string
  notebook_path: string
}
```

**优势**：
- 保留溯源能力（知道块来自哪个对话）
- 保持灵活性（块可以被多个对话引用）
- 可以实现"按对话筛选"和"全局搜索"两种视图

**UI 示例**：
```
右侧面板：
┌──────────────────────────────┐
│ 视图切换：                    │
│ ○ 当前对话  ● 所有分析块      │
├──────────────────────────────┤
│ 🔍 搜索分析块...              │
│                              │
│ ▼ NVDA Q4 分析               │
│   来自: "分析科技股" 对话     │
│ □ AMD Q4 分析                │
│   来自: "消费股研究" 对话     │
└──────────────────────────────┘
```

## 用户认知模型对比

### 方案 1：对话中心

**用户心智模型**：
```
对话 = 一次完整的研究会话
块 = 对话中产生的分析结果
```

**类比**：类似文件夹系统
- 对话 = 文件夹
- 块 = 文件夹里的文件

**适合人群**：习惯传统对话式 AI 工具（ChatGPT, Claude）的用户

---

### 方案 2：块中心

**用户心智模型**：
```
块 = 独立的分析成果
对话 = 创建/修改块的工具
```

**类比**：类似 Notion Database
- 块 = Notion 页面
- 对话 = 创建页面的入口之一

**适合人群**：专业投研人员，习惯项目管理工具（Notion, Airtable）的用户

---

## 建议

### 如果用户画像是：
- **金融分析师/专业投资者**：倾向方案 2（块中心）
  - 理由：需要长期跟踪、模板复用、灵活查询

- **个人投资者/轻度用户**：倾向方案 1（对话中心）
  - 理由：认知负担低，即问即答，不需要管理复杂结构

### 如果产品定位是：
- **AI 投研工作台**：方案 2
- **AI 投研助手**：方案 1

### 如果考虑迭代路径：
- **MVP 阶段**：方案 1（更简单，更容易理解）
- **成熟产品**：方案 2 或混合方案（支持专业用户需求）

## 附录：其他产品参考

| 产品 | 架构模式 | 说明 |
|------|---------|------|
| ChatGPT | 对话中心 | 所有内容归属于对话，无独立"文档"概念 |
| Notion AI | 块中心 | AI 生成的内容是独立页面，可在多处引用 |
| Jupyter Notebook | 块中心 | 每个 notebook 是独立文件，不绑定到"对话" |
| Google Docs | 混合 | 文档独立，但可以记录评论历史（类似对话） |
| Perplexity Pro | 对话中心 | 搜索结果归属于对话，但可以收藏（接近混合） |
